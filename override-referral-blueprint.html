A

Funding — where the payout money comes from

staking.sol
_routeStakeUsdt

Before anyone earns, every USDT stake is split four ways. Override + referral are both paid from one pool — the leadership pool (the buffer). It is funded at stake time, so payouts are pre-financed, not minted.

Requirement · pool is funded per stake
Each stake routes leadershipBps + referralReserveBps of its USDT into the leadership pool (the buffer that backs both override and referral), tradingBps to the trading wallet, stakeLiquidityBps to LP/buffer, and the remainder to profit. The four shares plus the referral reserve can never exceed 100%.
enforced in _routeStakeUsdt (staking.sol:683) · invariant in setStakeConfig
_routeStakeUsdt(lp, usdtAmount)staking.sol:683
// referral reserve is read LIVE from the leadership module, then clamped to the remaining budget
uint256 refReserve = leadershipBps > 0 ? _referralReserveBps() : 0;
uint256 budget = BPS - leadershipBps - stakeLiquidityBps - tradingBps;
if (refReserve > budget) refReserve = budget;              // can never push the split > 100%
uint256 toLead = (usdtAmount * (leadershipBps + refReserve)) / BPS; // → the BUFFER pool (override + referral)
uint256 toTrading = (usdtAmount * tradingBps) / BPS;               // → trading capital (generates the yield)
uint256 toLp = (usdtAmount * stakeLiquidityBps) / BPS;
if (toLead > 0) assets.creditBalance(address(leadership), USDT, toLead);
uint256 toProfit = usdtAmount - toLead - toTrading - toLp;         // remainder → profit

B

Override — the two-leg breakaway passive

leadership.sol
_dailyRate / recordStake

A member has a LEFT and a RIGHT leg (their two children in the binary tree). Each leg pays a daily rate on that leg's group volume. This is the core formula the whole module exists to compute:

daily(leg) = legVolume × overrideMultiplier × ( yourRate − topDownlineRate )
_dailyRate(m, leg)leadership.sol:312
if (aStake == 0 && rFloor == 0) return 0;      // GATE 1 — liveness
uint256 vol = legVolume[m][leg];
uint256 mult = overrideMultiplierBps;
if (vol == 0 || mult == 0) return 0;         // GATE 2 — no volume / multiplier off
uint8 cap  = _highestRankForStake(aStake);        // rank your SELF-STAKE backs (the rule)
uint8 allow = cap > rFloor ? cap : rFloor;         // …OR the admin-assigned rank (override)
uint8 rk = rank[m];
uint256 myRate = rateForRank(rk <= allow ? rk : allow);  // GATE 3 — earning rank
uint256 top = legTopDownlineRate[m][leg];
if (myRate <= top) return 0;                  // GATE 4 — broken away
return ((vol * mult) / BPS) * (myRate - top) / BPS;

B1The four gates — what must be true to earn

Requirement · liveness (the safety net)
You earn override only while you hold a live self-stake (activeStake > 0) or the admin has assigned you a rank (rankFloor > 0). Close your position and the rate drops to 0 the same block.
_dailyRate:315 · same test guards _payReferral:440, claim:641/649, release:677
Requirement · earning rank = RULES, unless admin overrides
Your earning rank is min( cached rank , max( stake-backed rank , rankFloor ) ). The rules — group volume + active directs + a per-rank minimum self-stake — set the natural rank; a stake below the floor throttles earning down. An admin-assigned rankFloor overrides the rules, and wins when higher.
_dailyRate:319–324 · promotion mirror in _effectiveRank:509
Requirement · breakaway differential
You earn on the gap between your rank rate and your leg's strongest downline rate. When a downline reaches your rank (myRate ≤ top) that leg has broken away → 0. Income only ever winds down through breakaway, never through a downline unstake.
_dailyRate:326 · tracker raised in _rollOne:411 & _propagateRankUp

B2The rules the gates read

Natural rank needs all three: the group-volume + directs threshold (rankFor), AND the per-rank minimum self-stake (minStakeForRank). All three thresholds are admin-tunable state — setRankRequirement(r, gv, directs, minSelfStake), the promotion lever. The rate per rank is fixed at rank × 5% (rateForRank).

Rank is a monotonic high-water mark (once reached, kept) — but earning is re-priced live by min-stake, so a leader who withdraws their own stake keeps the title yet earns at the rank their remaining stake backs. B3Processing — from a downline stake to a withdrawal

1
Stake lands → recordStake(staker, V)
Staking credits the pool (§A) then calls in. Guarded onlyStakingOrAuth; a no-op when disabled or V=0. leadership.sol:367
2
Staker's own legs settle first, then activeStake += V
Settling while still closed books nothing and re-stamps the clock — a revived member's dormant gap earns nothing. Then their rank is recomputed (a new self-stake can clear a floor). recordStake:373–379
3
Volume rolls UP the binary tree → _rollUp / _rollOne
For each ancestor up to depthCap: settle that leg at the OLD rate, raise its breakaway tracker from the path below (maxRateBelow telescopes), add V to leg + group volume, recompute the ancestor's rank. leadership.sol:386–427
4
Time passes → _settle books the accrual
Each settle adds dailyRate × secondsElapsed / secondsPerDay into legAccrued. Every rate-changing event settles first, so a later change can never claw back what already accrued (loss-proof). leadership.sol:340
5
Member claims → claimPassive(leg) / claimPassiveBoth()
Settles, then moves legAccrued → heldIncomeOverride. Blocked by the liveness gate (STAKE_CLOSED) unless you hold a live stake or an assigned rank. leadership.sol:639 / 663
6
Member withdraws → releaseHeld()
Moves held override (+ referral) from the pool to your withdrawable vault balance via balanceTransfer (CEI). Reverts if the pool is short — the company keeps it funded. leadership.sol:676 / 687
C

Referral — the flat unilevel bonus

leadership.sol
_payReferral

Separate from the override: a one-shot bonus paid up the affiliate tree every time someone in your sponsor line stakes. Per-level rates, self-funded by the reserve set aside in §A.

Requirement · the per-level plan & the self-funding identity
Rates are a PER-LEVEL array — referralLevelBps[i-1] is level i's rate — admin-tunable per level via setReferralLevels (or the flat wrapper setReferralPlan). The reserve set aside per stake is the SUM of all levels, so what's paid out exactly equals what was reserved. Live default: 5% direct + 1% × 5 = 10%.
rates: setReferralLevels / setReferralPlan · reserve = Σ referralLevelBps (referralReserveBps)
Requirement · a closed upline earns nothing
The same safety-net gate as override: an upline with activeStake == 0 && rankFloor == 0 is skipped — the walk continues to their upline, but they receive no referral while their own stake is closed.
_payReferral:440
_payReferral(staker, V)leadership.sol:430
uint256 maxLevel = referralLevelBps.length;       // walk one level per configured rate
for (uint256 level = 1; level <= maxLevel; level++) {
    (up, ) = accounts.getAffiliate(up);            // walk the AFFILIATE tree (not the binary tree)
    if (up == address(0)) break;
    if (activeStake[up] == 0 && rankFloor[up] == 0) continue; // GATE — closed upline skipped
    uint256 bps = referralLevelBps[level - 1];      // this level's admin-set rate
    uint256 amt = (V * bps) / BPS;
    heldIncomeReferral[up] += amt;                  // held, released via releaseHeld()
    emit ReferralPaid(up, staker, level, amt);
}

C1Processing — one stake, up to six payouts

1
Fires inside recordStake, after the volume roll-up
Same trigger as the override; returns immediately if both rates are 0 (referral off). recordStake:381 → _payReferral:430
2
Walk the affiliate tree, level 1 → 1+indirectLevels
Distinct from the override's binary tree: referral uses getAffiliate (the sponsor line). Live depth = 6 levels (1 direct + 5 indirect).
3
Credit each eligible upline → heldIncomeReferral[up]
Amount = V × bps / BPS. Closed uplines are skipped (still counting the level). Accrues into the SAME held bucket as override.
4
Withdraw via the shared releaseHeld()
Override + referral release together, from the same pool, in one call. leadership.sol:687
? Reason
Two different trees on purpose: the override follows the binary tree (placement) so leg balance matters; the referral follows the affiliate tree (who you personally sponsored). Self-funding means referral can never outrun its own reserve — it is Sybil-neutral by construction.
D

Invariants that hold across both

the rules that never bend
Held-then-release
A claim only WRITES the ledger (legAccrued → held); releaseHeld is the only thing that moves USDT and it reverts if the pool is short. So the daily yield can never overdraw the pool — a shortfall defers a payout, it never bricks staking.
_claimPassive:663 · _releaseHeldFor:687
No demotion from a downline unstake
A downline closing never reduces an ancestor's group/leg volume, rank, or accrued passive — recordUnstake only shrinks the closing member's own self-stake. Override winds down solely through breakaway.
recordUnstake:460
Loss-proof settle-before-change
Every event that moves a rate — a downline stake, a rank change, a breakaway, a close, a revive — calls _settle first, pricing the elapsed days at the OLD rate. Nothing already earned can be re-priced by a later change.
_settle:340, called from _rollOne, _setRankSettle, _claimPassive, record hooks
